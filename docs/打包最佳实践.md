# 打包最佳实践 / Packaging practice

[中文首页](../README.zh-CN.md) · [English README](../README.md) · [排障指南](troubleshooting.md) · [实测记录](tested-games.md)

适用于 **NxLauncher 0.1.5**。默认路径是：**核对输入 → 检查 Mac 环境 → 构建并自动导出 App → 主动启动 → 分项验收**。iOS 是单独选择的目标，不是 Mac 构建的必经步骤。

The default workflow is inspect → Mac doctor → build and automatic app export → explicit launch → separate runtime checks. iOS is an explicit target. Historical packaging is not current-release validation.

## 1. 一款游戏，一个输入目录

用户自备合法游戏与 `prod.keys`，不提供获取来源。下面只示意目录命名，文件名中的 ID／版本必须与自己的包相符。

```text
~/Games/MyGame/
  Game [01007EF00011E000][v0].nsp
  Game Update [01007EF00011E800][v1114112].nsp
  [DLC][01007EF00011F001].nsp

~/Keys/prod.keys
```

本体也可为 XCI。不要把两款游戏的本体混在同一目录，避免混入不适用更新。输入直接放在选择的目录中；保留原文件，密钥独立存放，不加入版本控制。流水线无需输入固件。

DLC 的识别、解包、打包、运行枚举和实际功能验收是不同步骤；不能承诺“放进去就全部可玩”。每次变更更新／DLC 后重新检查计划。

## 2. 先准备启动器与目标环境

源码方式：

```bash
git clone https://github.com/nocmt/nxlauncher.git
cd nxlauncher
./bootstrap.sh
python3 Tools/pack_pipeline.py doctor --target mac
```

`bootstrap.sh` 默认 Mac，iOS 使用 `./bootstrap.sh --target ios`；它选择 Python 3.12+，准备子模块／补丁、虚拟环境和启动器，会写入仓库并按清单安装固定版本依赖。CPython 3.13 arm64 可使用 bundled wheels 离线安装；其他解释器 ABI 可能需要联网下载固定版本。`./bootstrap.sh --check --target mac` 跳过安装与构建，但检查可能写入临时文件或诊断会话，不是零写入承诺。目标能力使用 `doctor --target mac|ios` 核对。

Mac 游戏按 Apple Silicon、macOS 26+、完整 Xcode、macOS SDK 和 Metal 工具链准备；**不要求 iOS SDK**。游戏构建还需 arm64 .NET 10 SDK／运行时、`zstd`、`spirv-cross` 和所选 Python 的依赖。iOS 目标才增加 iPhoneOS SDK、`xcodegen` 及相关签名条件。

环境面板支持确认后安装固定 brew 白名单中的依赖。核对目标与安装命令，不额外安装无关工具。Xcode 与 Homebrew 从 [Apple](https://developer.apple.com/xcode/) 和 [brew.sh](https://brew.sh/) 官方入口准备；具体检查与修复见[排障](troubleshooting.md#环境检查与依赖安装)。不要向系统 Python 全局混装依赖。

磁盘预算要包括：原始游戏、解包结果、重写模块、着色器、iOS 构建中间目录（若使用）和每份导出副本。不要依赖固定“原包倍数”或首次构建分钟数。

## 3. 核对计划，再开始构建

```bash
python3 Tools/pack_pipeline.py plan --target mac \
  --game-dir "$HOME/Games/MyGame" --keys "$HOME/Keys/prod.keys"
```

重点看：本体 title ID、所选更新、DLC、profile 是否正式／临时、工作目录、密钥路径是否可用。路径存在不代表密钥能解开该版本；以解包结果为准。

profile 包含模块、内存、版本和 shader 信息，有 profile 不等于实测通过。无档案时生成的临时配置／survey 只是移植起点；不要将其输出直接当成支持承诺。

游戏设置界面将语言、帧率目标和掌机／主机运行模式呈现为横排分段单选；它们分别写入该游戏的 `env.txt`。不要把 UI 选择项与游戏兼容性结论混为一谈。

```bash
python3 Tools/pack_pipeline.py build --target mac --graphics-api auto \
  --game-dir "$HOME/Games/MyGame" --keys "$HOME/Keys/prod.keys"
```

`build` 默认 `--target mac`，成功后自动导出 `.app`，**不自动启动**。保留命令输出中的实际产物路径与会话 ID；不要靠相似 App 名猜测哪一份是刚生成的。

`build`、`doctor`、`export` 的图形参数为 `--graphics-api auto|nvn|vulkan|gl`；`plan` 不接受该参数。先使用 `auto`；仅在明确游戏需要的路径时强制选择，不将切换 API 作为兼容性保证。

## 4. 让缓存可追溯

工作目录位于 `<游戏目录>/<TITLE_ID>_build/`，阶段日志位于 `logs/`。解包、重写和着色器中间产物可被复用；不同上游版本、工具链或 shader chain 下不能默认兼容。

| 情况 | 建议 |
|---|---|
| 同一输入的常规重试 | 先正常 `build`，保留缓存和第一次失败的日志。 |
| 明确需要重新构建 | `build --rebuild`，先保存诊断和有价值的旧产物。 |
| shader／metallib／chain 不一致 | 修好环境后用 `build --rebuild-shaders`，等待对应阶段完成。 |
| 更换游戏更新或图形 API | 重新 plan，核对实际版本与目标；记录新会话，不混用旧运行结论。 |
| 怀疑工具缓存损坏 | 先退出启动器，按[排障](troubleshooting.md#finder-与终端环境不同)备份处理工具缓存；不要删除存档。 |

不要编辑 chain 标记绕过校验，不要在构建中移动目录或修改正在运行的脚本。新旧产物保存到不同导出位置，避免验收时误开旧版本。

## 5. 从已有工作目录导出

仅当工作目录的版本、资源与宿主完整匹配时使用。以下 ID／版本是示例；替换为自己的实际值。

```bash
python3 Tools/pack_pipeline.py export --target mac-app \
  --game 01007EF00011E000 --ver v1114112 \
  --work "$HOME/Games/MyGame/01007EF00011E000_build" \
  --out "$HOME/Desktop/MyGame.app"
```

`export` 的 target 是 `mac-app|ios-ipa|ios-ipa-unsigned`，与 `plan/build/doctor` 的 `mac|ios` 不同。导出为副本，需额外空间。不要通过手动拼接不同版本资源补齐失败目录。

默认字体采用开放 **NotoSansSC**，字体 helper 已本地验证。不同游戏的字形、布局仍需单独检查；第三方资源的分发范围以核对后的 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 为准。

## 6. iOS 单独构建与签名

```bash
python3 Tools/pack_pipeline.py doctor --target ios
python3 Tools/pack_pipeline.py plan --target ios \
  --game-dir "$HOME/Games/MyGame" --keys "$HOME/Keys/prod.keys"
python3 Tools/pack_pipeline.py build --target ios --graphics-api auto \
  --game-dir "$HOME/Games/MyGame" --keys "$HOME/Keys/prod.keys"
```

已有完整工作目录也可导出未签名 IPA：

```bash
python3 Tools/pack_pipeline.py export --target ios-ipa-unsigned \
  --game 01007EF00011E000 --ver v1114112 \
  --work "$HOME/Games/MyGame/01007EF00011E000_build" \
  --out "$HOME/Desktop/MyGame-unsigned.ipa"
```

- 未签名 IPA 需要适当重签才可安装。已签名路径 `ios-ipa` 也依赖本机有效身份与描述文件。
- 最终资源／DLC 在签名前进入包；签名后改资源会破坏封印。
- 核对 bundle ID、设备、签名有效期及所需权限。重签可能丢失内存／地址空间相关 entitlements；签名校验通过不代表权限正确。
- iOS 需真机实际验收，不能用模拟器结果或 IPA 存在代替。安装成功、能启动、能操作和存档可用也要分开记录。
- 不保证任意侧载工具、账号类型或设备均可使用；以当前 Apple 规则、设备和最终签名结果为准。

具体故障路径见 [iOS 排障](troubleshooting.md#ios-签名安装与真机)。不将含游戏数据的 IPA 当作可随意发给他人的普通软件附件。

## 7. 验收四件事

| 验收 | 做法与边界 |
|---|---|
| **身份与结构** | 核对 title ID、版本、目标、构建会话、实际产物路径与必要资源，避免同名的其他项目 App 混入结果。 |
| **签名** | 验证签名及权限。本次计划提供 Developer ID 签名、未公证 preview，实际资产签名验收看最终清单；本地 ad-hoc 验证不代表 Apple 公证。 |
| **实际运行** | 主动打开 App，分别记录标题、场景、输入、声音、画面异常与运行时错误。 |
| **存档往返** | 备份后测试保存、退出、重开、读档；不能用一次启动代替。 |

```bash
plutil -lint "$HOME/Desktop/MyGame.app/Contents/Info.plist"
codesign --verify --deep --strict --verbose=2 "$HOME/Desktop/MyGame.app"
codesign -d --entitlements :- "$HOME/Desktop/MyGame.app"
```

以上是结构／签名检查，不会代替运行验收。当前 Mac 导出的支持目录通常为：

```text
~/Library/Application Support/nxnative/<TITLE_ID>/
  save/
  env.txt
  log.txt
  temp/
```

旧导出可能按 App 名命名。升级前备份新旧位置；不要误删 Application Support 来清理构建缓存。出现 `[RED]`、`CRASH` 或异常退出时保留上下文；没有这些字符串也不能证明全部正确。

## 8. 留下别人能复查的记录

```bash
python3 Tools/pack_pipeline.py diagnostics \
  --out "$HOME/Desktop/NxLauncher-session.zip" --session SESSION_ID
```

记录启动器版本、精确上游 commit／补丁、游戏版本、目标、系统／芯片、graphics API 和检查项。诊断包可能含会话／环境／路径信息，即使做了脱敏也应在提交前打开检查，不附游戏数据、密钥、存档或签名凭据。详见[诊断包检查](troubleshooting.md#诊断包内容检查与反馈)和[隐私说明](privacy.md)。

历史成功清单见 [tested-games.md](tested-games.md)：智慧的再现 1.1.0 有用户正常游玩反馈；旷野之息与动森按实际日志标记有限运行。三款均未在最终 0.1.5 基线重新游玩验证。profile 列表不是成功清单，MacNativeGames 的 117 FPS 不属于 NxLauncher 证据。

启动器自身的发布、校验和可选 Developer ID／公证流程见[发布文档](releasing.md)。本指南不执行提交或发布，也不预称任何资产已公证。
