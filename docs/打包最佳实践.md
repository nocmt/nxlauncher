# 打包最佳实践（简明版）

> 2026-10-21 · 基于 nxnative 移植（`github.com/seedds/nxnative`）+ 我们本地的补丁
> 一句话：**把游戏文件交给上游的流水线，它出 IPA；再把同一个宿主打成 Mac `.app`。**

---

## 0. 一次性准备（每台机器做一次）

```bash
brew install xcodegen zstd spirv-cross
brew install --cask dotnet-sdk
python3 -m pip install lz4 capstone fonttools
```

需要 **Xcode**（含 iOS 26 SDK）、**macOS 26+**、**Apple Silicon**。磁盘按「NSP 总大小的 2 倍 + 10 GB」准备。

> `lz4` / `capstone` / `fontTools` 建议装进**独立 venv**（我们用的是 `CodeLeaning/nxnative-venv`），别污染系统 Python。

---

## 1. 准备游戏文件

一个游戏一个文件夹，**本体 + 更新包 + DLC** 放一起：

```
~/Games/BotW/
  The Legend of Zelda [01007EF00011E000][v0].nsp      # 本体（也可以是 .xci -cart）
  The Legend of Zelda [01007EF00011E800][v1114112].nsp # 更新包
  [DLC][01007EF00011F001].nsp                          # 追加内容（可多个）
```

- **本体可以是 NSP 或 XCI**（上游脚本两种都吃）。
- **DLC 放进去就会被自动打包**进 IPA（`aoc/<index>/`），游戏里「已下载的追加内容一览」就会出现。
- **不需要固件文件**。上游整条流水线只认 `prod.keys`，没有固件这一项。

---

## 2. 打包（一条命令）

```bash
cd nxnative-src
python3 scripts/build_ipa_from_nsp.py ~/Games/BotW -k ~/keys/prod.keys
```

产物：同目录下的 `ZeldaBreathOfTheWild.ipa`（**未签名**）。

| 耗时 | 情况 |
|---|---|
| **30–60 分钟** | 第一次（要翻译并编译 19,592 个着色器，BotW 约 24 分钟） |
| **约 10 分钟** | 之后（解包结果和着色器缓存都在） |

**缓存是让「第二次快」的唯一原因**：
- 解包结果留在 `<id>_build/extract/`（默认保留）；
- Metal 着色器库缓存在 `<id>_build/shader/cache/`（按「源码 + 编译参数 + 编译器」做 key）；
- 日志按步骤分文件留在 `<id>_build/logs/`——**出问题时先看这里**。

---

## 3. 装到 iPhone

未签名的 IPA 装不上（iOS 要求签名）。两种办法：

| 办法 | 适合谁 | 怎么做 |
|---|---|---|
| **侧载工具重签**（推荐给同事） | 别人 | 把 IPA 丢给 Sideloadly / AltStore / LiveContainer，它们换成你自己的证书 |
| **自己签 + 直装** | 自己有 Mac + Xcode | 见下面第 4 步，然后 `xcrun devicectl device install app` |

> 免费 Apple ID 签的包**只有 7 天**有效期；付费账号一年。

---

## 4. 我们本地的流程（多了签名 + Mac 版 + DLC）

```bash
# 4.1 生成 Gen/ 并编译 iOS app（自动签名）
bash miniapps/nxbuild/sign-build.sh

# 4.2 把游戏文件/着色器/DLC 塞进 bundle，然后按描述文件重新签名
AOC=/tmp/aoc-ios bash miniapps/nxbuild/finish-install.sh

# 4.3 打 IPA：一份带签名、一份未签名
bash make-signed-ipa.sh
bash miniapps/nxbuild/make-unsigned-ipa.sh

# 4.4 打 Mac .app（同一个宿主的 macOS 版本）
bash make-mac-app.sh
```

`sign-build.sh` 会自己重建 `Gen/`（源码符号链接 + 嵌入模块 + 着色器表 + 字体 + 图标），**所以项目搬了家也不用手工补产物**。

## 5. 产物清单（以 BotW 1.9.0 为例）

| 产物 | 大小 | 条目 |
|---|---|---|
| `BotW Native.app` | 17 GB | 宿主 1.9 MB + 22 个重写模块 + 25,846 个 metallib + 41,062 个游戏文件 + 7,094 个 DLC 文件 + 11 尺寸图标 |
| `ZeldaBreathOfTheWild-signed.ipa` | 15.82 GiB | 94,806 个条目 |
| `ZeldaBreathOfTheWild.ipa`（未签名） | 15.82 GiB | 94,803 个条目 |

**两个 IPA 的内容逐字节一致**，只差签名那两个条目（`_CodeSignature/` 和 `embedded.mobileprovision`）。

## 6. 验收（别跳过）

```bash
# 包里该有的都在
codesign --verify --strict "<app>" && echo OK
codesign -d --entitlements - "<app>"        # 权限逐条看，别只看 exit 0
plutil -lint "<app>/Contents/Info.plist"

# 跑起来看日志
L="$HOME/Library/Application Support/BotW Native/log.txt"
grep -cE '\[RED\]|CRASH' "$L"               # 必须是 0
grep -E "aoc: reporting" "$L"               # DLC 有没有挂上
grep -E "power up to frame" "$L" | tail -1  # 帧率
```

**图标**（必须是游戏原画，不是通用 "exec" 图标）：

```bash
xcrun swift miniapps/nxbuild/appicon2.swift   # 看 Finder / Dock 实际显示哪个
```

## 7. 这套流程里踩过的坑（都是真踩过）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **重签丢权限**：用 Xcode 生成的 `*.xcent` 重签，`codesign --verify` 照样通过，但 `increased-memory-limit` / `extended-virtual-addressing` 没了（装得上但跑不对） | 一律从**描述文件**取 entitlements（`finish-install.sh` 已改好） |
| 2 | **DLC 必须在重签前放进 bundle** | 资源封印覆盖整个 bundle，放晚了签名就白签 |
| 3 | **宿主不在 `Contents/MacOS/`** → 进程不是 bundle 成员 → Dock 显示通用 "exec" 图标 | 宿主和启动器同放 `Contents/MacOS/` |
| 4 | **iOS 模拟器跑不了**（不是配置问题）：Apple 把模拟器 SDK 里的 Metal 4 API 整块拿掉了 | iOS 端必须有真机；验证走 Mac `.app` |
| 5 | **绝对路径写死** → 项目一搬家就全线断 | 搬完家**全量 grep** 旧路径，别只改主脚本 |
| 6 | **iOS 手柄映射按位置硬编码** → PS5 上 ○/✕ 跟游戏里的 A/B 对调 | 用 `dm_padmap.h` 按厂商分；`DM_PADMAP=nintendo\|xbox` 可强制 |
| 7 | **每款游戏都要一份画像**（`dm/games/<id>/`） | 没有画像的游戏：上游能出「尽力而为」的包，**可能起不来**（见启动器方案） |
| 8 | 别在脚本运行期间原地编辑它 | bash 是按字节偏移增量读脚本的，改了会报莫名其妙的语法错 |

## 8. 每款游戏的"画像"是什么（通用的关键）

`dm/games/<title id>/` 下：

- `game.tsv` —— 身份（title ID、已知的 build）、代码模块、RomFS 标记、**内存分配**、NVN 驱动表、App 名称与 bundle ID、目标帧率；
- `shader_map.tsv` / `shader_facts.tsv` / `shader_pairs.tsv` / `c1_full.tsv` / `pso_manifest.tsv` —— 着色器表；
- `dmsh_chain.h` —— 着色器链版本。

**上游已有 16 款**（马里奥、密特罗德、宝可梦火龙…见 README 的 Games 表），BotW 是其中之一。
没有画像的游戏，上游会先写一份 survey、再生成一份**临时画像**（`profile_guess.py` 猜图形 API、模块、着色器来源、内存分区），出的包**可能起不来**——这一步是人工活，不是自动的。
